# session-audit: design

Status: designed against architecture v1.33 and design guide v1.17. The normative rules are in [`interface.md`](interface.md); this document records why, and the internal structure. It never restates the interface's tables.

Section references (§N) point to `../awkit-docs/architecture.md` unless marked "design guide" (`../awkit-docs/design-guide.md`).

## Role and layer

Layer 3 (workflow), post-v1 (§4, §19). Analyzes Claude Code session transcripts: deterministic usage analytics from a store of counts, and model-written retros over a bounded, redacted digest. It is a skill-wrapper tool (§5.5, design guide §11) with the slot `audit`, kind `audit`, default skill `session-audit:audit` bundled in `plugin/`. It works fully standalone: the only sibling it calls is claude-session, and only the retro half requires it.

## Uses

| Tool | Binding | Used for | Required |
|---|---|---|---|
| claude-session 0.45.2 or later | A (call by name, parse `--json`) | `list` and `status` for harness snapshots during `ingest`; `start --dry-run`, `start`, the adopting `exec --session-id`, `status`, `forget --purge`, `stop` and `--version` for retro runs | Optional for `ingest`, `sessions`, `usage`; required for `retro run` |

Not used: agent-spawn, wtctl, termctl (a headless retro needs no window or worktree), memoctl (nothing is written to notes), notice-route (hooks are wired by the user or the harness), forgectl, ticketctl. A missing claude-session makes `retro run` exit 12 with `details.reason: claude_session_missing` and the install command in the message; one older than 0.45.2 (0.45.0 added `--tools`; 0.45.2 is the first release whose sandboxed `report` works for a default `uv tool install`) exits 12 `claude_session_too_old`.

Consumed by: self-improve (post-v1) through `retro show --json`; awkit through the read commands, `validate --json` and the cron block. session-audit knows neither.

## Resolved open topics

The architecture left four topics open (§20). They are resolved as follows.

| Topic | Resolution | Interface |
|---|---|---|
| What is audited | Every Claude Code transcript on disk, with claude-session records only as optional enrichment; usage, tools, errors, denials and cost per session, agent and day; retros over chosen scopes | [Ingest rules](interface.md#ingest-rules), [Harness enrichment](interface.md#harness-enrichment) |
| When it runs | `ingest` hourly from cron or on demand; retros only on explicit command, or from an opt-in weekly cron line; never at session end | [Cron](interface.md#cron), [Retro lifecycle](interface.md#retro-lifecycle) |
| Output | Counts in a store; retros as a closed JSON artifact plus findings and improvement candidates, read with `retro show --json` | [Retro artifact](interface.md#retro-artifact) |
| How improvements are applied | They are not, here. Candidates are suggestions; self-improve turns them into proposed edits a human accepts (§12.1) | [Overview](interface.md#overview) |

## Decisions

| # | Decision | Why | Interface |
|---|---|---|---|
| D1 | Read every transcript on disk, harness data only as enrichment | Usage is most useful across everything run by hand and by the harness; the tool must work with no harness installed; claude-session exposes no transcript listing, tokens or per-session cost | [Ingest rules](interface.md#ingest-rules) |
| D2 | A store of derived facts with no conversation text | Claude Code deletes transcripts after about 30 days and claude-session sessions leave its commands after `forget`; counts survive, text would add a secret and injection surface | [Ingest rules](interface.md#ingest-rules) |
| D3 | `ingest` from cron, retros on demand | `ingest` is free, idempotent and must run regularly anyway; a retro costs money and reads untrusted text; a retro per session end would recurse through the same hooks | [Cron](interface.md#cron) |
| D4 | The retro session sees only a pre-built, redacted, fenced digest in a sandboxed third-party-reading session | Transcripts hold third-party text and secret-shaped strings; the built-in `audit` kind is trusted and unsandboxed; a prompt-injected retro must not reach credentials or the network; the manifest is control data with no transcript text; the tool verifies the effective tools, isolation and every inherited safety setting with a dry run before anything is stored, so a launch problem costs nothing and the guarantee never depends on claude-session's config | [Digest](interface.md#digest), [Retro launch](interface.md#retro-launch) |
| D5 | A closed artifact whose evidence references the tool checks; numbers come from the store | Models invent facts; a reference to an item that is not in the digest is dropped; a consumer gets one stable contract; model text is redacted again before it is stored, because a retro outlives its digest; candidate risk is written by the tool | [Retro artifact](interface.md#retro-artifact), [Retro validation](interface.md#retro-validation) |
| D6 | Headless only in 0.x, through `claude-session start` and an adopting `exec` in the session's own working directory | A retro is a batch job; the dependency stays one tool, shareable without tmux or worktrees; interactive discussion is self-improve's role; the id is known before the model runs, so recovery, signals and cleanup act on an exact id, and a directory under the state directory would be refused by claude-session on every install | [Retro launch](interface.md#retro-launch), [Deviations](interface.md#deviations-from-the-design-guide) |
| D7 | Tokens exact, dollars carry a basis; a session's reported cost is its own main file's last cost line and is null under copied history | Cost lines do not always reconcile with tokens; mixing figures would mislead; a fork's cost lines may include its source's spend, so a session with copied history shows only an estimate; claude-session's per-run `cost_usd` is a different quantity and stays in the harness snapshot | [Cost](interface.md#cost) |
| D8 | Join to harness records only on the Claude Code session ids claude-session recorded, at query time, and refresh a snapshot whenever its `updated_at` changes | Guessing from directory names is spoofable; harness facts vanish at `forget`; snapshots keyed by claude-session id over a fixed window need no cursor, negative cache or queue, so nothing is skipped for good and read order does not matter | [Harness enrichment](interface.md#harness-enrichment) |
| D9 | Event-focused, budgeted digest with text only for failures | Successful tool output is where secrets concentrate and is rarely informative for a retro | [Digest](interface.md#digest) |
| D10 | No `audit.jsonl`; hash-only `log.jsonl`; hooks `pre-retro`, `post-retro`, `post-attention` | No external action is taken; a spend check before a model run is the one real veto point | [Hooks](interface.md#hooks), [Log](interface.md#log) |
| D11 | Standard config location with ownership checks, no repo layer | The threat (a trusted session editing config) is covered by the check plus the sandbox's write limits, and the check covers every command that can run a hook; a repo layer would let an environment value weaken a repo's safety | [Config](interface.md#config) |
| D12 | One `events` table, one deterministic owner per dedupe key (the kind is part of the key; owner order: largest output, earliest timestamp, native copy, path, offset; at most 8 stored copies per key, so owner work is bounded) | Content-block lines, compaction repeats and copied history after a fork count once, independent of ingest order and file rewrites for keys with at most 8 copies (more than 8: see the residual risk in [interface.md](interface.md#residual-risks)); a tool call and its error are distinct events; session values are derived from counted events and per-file facts, so a reread replaces them; `usage`, `sessions` and `show` aggregate at query time, so every counter, `--by tool` and `--tz` are exact; a reread deletes old events in short batches and every write transaction touches a bounded number of rows, so none nears the lease expiry | [Counting rules](interface.md#counting-rules) |
| D13 | Explicit retro scope, hard bounds, a content key over the digested sessions; a filter scope over the cap is trimmed, an explicit list is refused | Cost is predictable; an unchanged set of sessions never pays twice; the fence nonce stays random so a reader cannot forge the closing tag; the weekly schedule is never refused only for matching many sessions; `--max-turns` defaults to 12 (from a live run); the plan check, the cap and the same-key race are all settled in one order of checks, and the daily limit reserves a place when the row is inserted, so a launch problem is found by a dry run before anything is stored or counted | [Retro lifecycle](interface.md#retro-lifecycle), [Config](interface.md#config) |
| D14 | Blocking run, no resume, recovery by recorded id at the start of `retro run` and in `prune` | Follows review-run's shape with less surface; `validate` and `ingest --dry-run` stay read-only, `validate` only warns; recovery never looks a session up by label; recovery takes the retro's lease first, so two processes never recover the same retro, and it defers when claude-session cannot answer | [Retro lifecycle](interface.md#retro-lifecycle) |
| D15 | A hardened incremental reader | Transcripts can be unterminated, corrupt, huge or planted by a same-user process; natural data (a cut emoji) and planted data must not stop ingest | [Ingest rules](interface.md#ingest-rules) |
| D16 | No outputs outside the store | Notes written from a session that read untrusted text would reach later trusted sessions | [Safety](interface.md#safety) |
| D17 | Retention keys with a daily prune | Rows are small; model text and digests are not | [Retention](interface.md#retention) |
| D18 | No TUI in 0.x | The read commands cover reading; a TUI is a separate review surface | [TUI](interface.md#tui) |
| D19 | Identity echoes, a marker, a closed shape and a skill preflight in the plugin directories | The wrapper pattern for artifacts: claude-session accepts any artifact as `done`, so the tool must check; with no setting sources only plugin skills load, so `--skill` takes `plugin:skill` from the bundled plugin or `retro.plugin_dirs` and is checked before anything is stored with claude-session's own plugin path rules (credential locations such as `~/.claude` are refused, the bundled plugin of a `uv tool install` is allowed); the whole tree of a configured plugin directory must be owned by the user and not group or other writable (exit 12 `unsafe_plugin_dir`), while the bundled plugin gets no mode check because installed tool directories are group-writable by default; the skill name is limited to `[a-z0-9-]` so no path character reaches a path; the marker detects a skill that was not followed, not an attack | [Slot contract](interface.md#slot-contract), [Retro validation](interface.md#retro-validation) |
| D20 | The retro session's own transcripts are excluded by the exact project directory name recorded before launch, and removed by that name at cleanup | The digest would otherwise stay in Claude Code's store and be audited in turn; the name claude-session's session directory encodes to is recorded in `retro_sessions` when `start` returns, so cleanup never depends on data a crash may not have collected, and a launch whose name would exceed 200 characters, or whose session directory path holds a non-ASCII character, is refused; a row is kept until its cleanup is finished and its transcript directory is gone, and the exclusion is read at every file open | [Retro launch](interface.md#retro-launch), [Ingest rules](interface.md#ingest-rules) |
| D21 | The digest and the stored numbers come from the same bytes and one read snapshot of the store | The digest reads each file only up to its stored offset and skips a session whose file changed, so the key, the numbers and the evidence agree | [Retro lifecycle](interface.md#retro-lifecycle) |
| D22 | Time buckets are 15-minute UTC slots | Any `--tz` and a changed `time_zone` re-bucket exactly, because every real zone offset is a multiple of 15 minutes | [Counting rules](interface.md#counting-rules) |

## Live verification

Facts relied on, with the run that established them. Each becomes a regression test in the plan (`live` where it needs the real tool).

| Fact | Established by | Test |
|---|---|---|
| Transcripts are written per session under per-project directories with subagent files beside them; a project directory name is derived from the first-seen working directory; per-line working directories drift | Free read-only survey of a real corpus (Claude Code 2.1.x) | Synthetic corpus, parser tests |
| One API message is one line per content block (same message id); naive sums overcount about 2 times; deduping by message id (largest output) matches a run's reported usage exactly | Survey and a real run | Counting-rule unit test, `live` reconcile test |
| Timestamps are not monotonic (about a fifth of lines step backwards), so min and max are used | Survey | Synthetic corpus |
| About 30 days of transcripts are retained; a resumed session appends to the same file and may carry lines with another `sessionId`; a compaction is one boundary line counted once | Survey | Synthetic corpus, `test_a_compaction_boundary_is_one_compaction_and_a_resumed_session_stays_one_session` |
| Cost appears only in dedicated cost lines and can disagree with tokens | Survey (one of five sessions far off) | `cost_mismatch` flag test |
| Corrupt lines, NUL bytes and unterminated final lines exist; a 140 MB file parses in under a second with line-by-line reading (re-measured for the incremental reader: about 1 s; its test bound of 60 s is deliberately loose for slow CI) | Survey | Reader robustness tests |

| Transcripts record no labels or environment; a harness session is linkable only through the Claude Code session id that claude-session records | Survey | Join tests |
| A transcript file name equals the `sessionId` of every top-level line; subagent lines carry the parent's `sessionId` and their own `agentId`; no message uuid repeats across files in the surveyed corpus (forks were not observable); `cache_creation` has 5-minute and 1-hour counters | Survey (spike A) | Discovery, identity and cache-write fixtures |
| Each transcript field the tool reads (message tokens, tool call, tool error, denial, interruption, rejection, prompt, turn duration, compaction, reported cost, identity, agent link) exists under the key path the field map names | Survey (spike A, Claude Code 2.1.284 to 2.1.328) | One synthetic-corpus fixture per row of the transcript field map |
| The retro `exec` call works end to end for kind `audit` with third-party-reading settings: exit 0, frozen artifact, `cost_usd`, `num_turns`, sandbox active; about 40 s and a cent | Real runs (small model, synthetic digest) | `live` retro round trip |
| `implicit_done: true` hides failures; a malformed artifact and a missing report both end `done`; a misspelled skill ends `needs-input` | Real runs | Validation tests, `live` |
| A report command containing `$CSESSION_DIR` is denied in the sandbox; a literal absolute path works | Real runs | Skill test |
| The four plugin placeholder entries are needed for sandboxed Bash; claude-session adds them in a per-run copy | Real runs | `live` |
| Injected instructions in a digest were not followed in all five runs; fake secrets never reached an artifact; the built-in `ReportFindings` tool was once called, so the tool list is restricted | Real runs | `live` injection test |

| Evidence references: no invalid reference over five runs; finding counts vary between runs | Real runs | `live` |
| claude-session refuses a run whose working directory is under the state directory or any hidden home entry; its own per-session directory is exempt | Reading claude-session's published interface | `live`: `tests/test_live_retro_launch.py`, with the default state directory and with `XDG_STATE_HOME` set (the second test is billed and needs `SESSION_AUDIT_LIVE_LAUNCH=1`) |
| `status --json` reports the Claude session ids, the frozen artifact and the sandbox flag; a forgotten session reports as not found (a repeat `forget --purge` exits 10); `forget --purge` can leave `purged: false`, which `reconcile` finishes after 30 days | Reading claude-session's published interface and schema | Fake-tool tests, `live` cleanup test |
| Plugin path rules: a plugin directory that is `/`, `$HOME` or an ancestor, contains or is inside a credential path (`~/.claude`, `~/.config`, `~/.ssh`, and others), is under or contains a session-writable path or the state root, or holds any symlink (stricter than claude-session, which accepts in-tree relative ones), a special file or more than 10,000 entries, 64 MiB or 32 levels, is refused as `unsafe_plugin_dir`; a plugin directory located at a toolchain location such as `~/.local/share/uv` is allowed (it is not a credential location), but links inside the tree, such as `node_modules/.bin`, are refused; `start --dry-run` runs the same checks read-only | Reading claude-session's published interface (origin/main) | Preflight tests, launch plan check test with the fake tool |
| A failed `start` (launch validation after allocation) ends the run `not-started` and prints the error envelope `launch_failed` with `end_reason`, `hint`, `csession_id` and `run`; the session is real, not live, and `forget --purge` works on it; a pending run never adopted ends `never_adopted` and is never forgotten by claude-session itself | Reading claude-session's published interface and schema | Fake-tool tests of the `start` rows of the outcome mapping, `live` |
| `start --dry-run --json` allocates nothing, uses the placeholder id `cs-aaaaaaaa` for a new session, and prints `tools`, `implicit_done`, `sandbox`, `sandbox_lowered`, `repo`, `cwd`, `origins` and the resolved `profile`; a user or per-repo config of the `audit` kind shows in `origins` | Reading claude-session's published interface and schema | Launch plan check tests, one per safety setting |
| `transcript --paths --json` returns `files[]` (`claude_session_id`, `run`, `source`, `path`, `exists`) with `subagents[]`; the tool does not call it, because cleanup finds the retro's transcripts by the exact project directory name | Reading claude-session's published interface and schema | None (documented to explain why it is not used) |
| A project directory name is the first-seen working directory with every non-alphanumeric character replaced by `-` (91 of 91 files); only short ASCII names were observed, so a launch whose name would exceed 200 characters or whose session directory path holds a non-ASCII character is refused | Survey (spike A) | Plan check test, name-encoding unit test |
| Denials sit on user `tool_result` lines (`permissionDecision`, `toolDenialKind`); a denial has a tool-use id when its line has a `tool_result` block, an interruption has none | Survey (spike A) | Field-map fixtures |
| No line uuid appears in more than one top-level file (54,036 uuids) and no line carries a foreign `sessionId`; cross-file copies were not observable, so the owner tie-break is untested by real data | Survey (spike A) | Fork fixture, owner-rule property tests |

Still to verify (conservative default until then): macOS paths and sandbox behavior; a retro in `--cwd session-dir` and the name of its transcript project directory (self-exclusion depends on it); whether Claude Code shortens project directory names over 200 characters (the plan check refuses such a launch either way); how Claude Code encodes a non-ASCII character in a project directory name, per code point or per UTF-16 unit (the plan check refuses such a path); `session-env/<id>` under `$CLAUDE_CONFIG_DIR`; whether a retro session loads ancestor `CLAUDE.md` files or writes project memory next to its transcript; a real `claude --fork-session` transcript pair: whether copied lines keep the source `sessionId` (settles the owner tie-break); the retro session's offered tool and skill list (Claude Code's own bundled skills may remain loadable through `Skill`); a retro of more than 20 sessions (an explicit list is refused, a filter scope is trimmed); real-run behavior of a custom skill without a marker; the size of the events table on a real corpus (target under 200 MB for a year of heavy use).

## Modules

| Module | Responsibility |
|---|---|
| `cli` | argparse subcommands, global flags, exit-code mapping, JSON envelopes |
| `commands/` | the command registry: one module per command with its flags, checks and run |
| `command` | `Command`, `Context` and `Output`, the types a command runs with; every write to standard output goes through `Output` |
| `args` | flag helpers and validators shared by the commands; messages are fixed text |
| `errors` | the exit-code table and the closed error envelope (`CliError` enforces the schema) |
| `config` | YAML load with drop-ins, Pydantic validation, ownership checks, price table |
| `gateway` | the only place that spawns processes, touches the filesystem outside the store or reads the clock: `claude-session` calls (per-call timeouts and process groups), file opens, crontab |
| `textsafe` | the sanitizer (awkit's algorithm text as own code), `fix_surrogates`, the fence-tag neutralizer (`</untrusted` and `<untrusted`), and the display helpers (`show`, `dumps_json`, `write_stderr`) |
| `reader` | discovery, safe open (no symlinks, no FIFO blocking), incremental line reading, offset, inode and head and tail hash bookkeeping, line and file budgets |
| `reader` (discovery API) | Discovery API (issue #10, `reader.py`): `discover(ctx, paths)` (or `open_discovery(gateway, roots, excluded=, pruned_at=, paths=)`) opens the roots and returns a `Discovery` (a context manager; raises exit 12 `no_readable_roots`, exit 2 for a `--path` outside every root). `Discovery.candidates()` lazily yields `Candidate` records (raw `path` bytes, `rel`, `kind` main/subagent/workflow, `session_id` and `parent_session_id` from the path, `agent_id`, `workflow`, `project`/`project_dir`, `size`, `mtime_ns`, `dev`, `ino`), project directories then files by descending mtime; nothing is opened. `Discovery.open(candidate)` re-walks the path from the root descriptor with `openat`, checks the descriptor, asks `excluded` and `pruned_at` (the store's `retro_sessions` and `pruned_sessions`, read at that moment) and returns `Opened` (blocking file plus its `fstat`) or a `Skip` reason already counted in `Discovery.stats`. `read_meta(candidate)` reads `agent-<id>.meta.json` (64 KiB cap). `Discovery.warnings` gives the fixed tokens `scan_capped`, `root_unusable` and `dirs_unreadable`; `display_path` is the only way to show a path. The caller owns budgets (check them between `open` calls) and the `--since` session grouping; a `--rebuild` or `--session` run uses the same API. Pruned skips have their own counter (`stats.pruned`) because the ingest counts name none. A root that is group or other writable is unusable by design (a 0770 `~/.claude/projects` made under umask 002 needs `chmod g-w`; the exit-12 hint says so); an open failure other than `ENOENT` counts `files.unsafe` (conservative: the ingest counts have no "unreadable" name). |
| `parser` | `parse_line(data, ParseContext) -> LineResult`, a pure function: line-type tolerant parsing into events (the transcript field map): usage, tools, errors, denials, interruptions, timing, subagent links; a guard around every line |
| `derive` (issue #14, `derive.py`) | Query-time values; nothing is stored and no migration was needed (`events_session_counted` and `events_file` serve every query). `iter_session_values(conn, settings, ids=None)` (batches of 200 ids, in SQL: memory never grows with events), `session_values(conn, settings, id)` and `SessionValues.to_json()` (the Session object without `harness`, which #16 joins); `agent_values(conn, session_id, limit=1000)` returns `(agents, truncated)`. Buckets: `bucket_key(slot, 'day'|'week'|'month', zone)` and `Bucketer(zone)` (a slot's local date from its UTC start; keys `2026-11-20`, `2026-W47`, `2026-11`; None for no slot). Cost: `CostAccumulator(prices).add(model, TokenSums)` gives the exact `estimated` and `unknown_tokens` (a model without a price adds its four counters to `unknown_tokens` and nothing to dollars; `PriceTable.lookup` decides), `is_mismatch`, `reported_sum(values, time_filtered=, splits_session=)` (all-or-null; also null for no contributor), `Cost.to_json()`, `usd`/`usd_json`. SQL pieces for #17: `COUNTED_EVENTS_SQL` (counted events with `model` and `tool` of an error or denial taken from the call whose key is its `ref`, the counted copy first) and `SECONDS_MS_SQL` (sum this, divide by 1000 once: `seconds_of`). Arithmetic: tokens and turn milliseconds are integers; dollars are `Decimal` (a price read through its shortest `repr`), summed exactly over all events and models and rounded half up to micro-dollars once, at the end (a total from the exact sum of its events, never from rounded rows); `reported_usd` is rounded to micro-dollars when read, so its sums are exact; a JSON number is the shortest float of that decimal. Judgment calls: `cost_mismatch` compares `abs(reported - usd(estimated))` with `mismatch_margin * usd(estimated)` (relative to the printed estimate; an estimate printing 0 makes any positive reported figure a mismatch) and ignores `unknown_tokens` (the figures are compared as printed: `abs(reported - usd(estimated)) > mismatch_margin * usd(estimated)` in micro-dollars); copied history is a counted-0 row in the main file whose counted owner has another `session_id` (an owner in an agent file of the same session is not copied history); `old_rules` is any of the session's files with a `rules_version` below `meta.rules_version`; `no_timestamps` follows rule 8 (an event with `ts` null, not a null slot); a session with no stored main file has no reported cost and its project from the directory name |
| `eventstore` (issue #13, `eventstore.py`) | The writer of the `events` table. `event_key(kind, id)` and `event_ref(tool_use_id)` (sha256 of the kind, a NUL byte and the id, first 16 hex characters; a ref equals the key of its call); `dedupe_id(event, file_id, line_offset)` (the parser's id, else `f"{file_id}:{line_offset}"` with `:{block}` for tool_call, tool_error and message events); `place_events(conn, FileRef, [(Event, line_offset)])`, the within-file rule and `place_copy` for one chunk inside the caller's transaction (it reads at most the 8 stored rows of a key per event and returns the `copies_dropped` to add per file id; a copy already stored for the file changes only when a later line has a strictly larger output, and keeps the offset of its first line); `delete_batch` and `delete_old_events` (batches of at most 2,000 rows, each its own transaction, each repairing the owner of every key it deleted a counted row from, the last clearing `rereading`); `read_file(store, lease, opened, previous, rules_version=, file_budget=, run_deadline=, force=, meta=)` for #15 to call once per opened candidate. `read_file` resets the row on a reread, finishes a pending deletion first (and returns with `reading` false when a budget ended it), then reads lines through `IncrementalRead` and `parse_line` with no transaction open and commits each chunk of at most 10,000 lines or 2,000 events in one `Store.transaction()` that calls `lease.check_still_holder(conn)` first and holds the file row with its offset and hashes, the sessions and agents rows (ids from the `Candidate`, so a subagent file read before its parent names its session; `meta` adds the agent type and parent tool-call id), the events with their owners and the per-file facts. A chunk closes before a line whose events would pass the event cap, and the events of one line are never split; a line yields at most 1,002 events (1,000 blocks, a denial and an interruption), so with the production cap of 2,000 a chunk never exceeds it (only the scaled-down caps of tests can meet a line larger than the cap, which then stays whole in one chunk). Before every transaction the writer renews the lease when less than 60 s is left (`LEASE_MARGIN_SECONDS`), so none starts near the 120 s expiry; a busy store is the store's retryable exit 12 and is not caught here. `copies_dropped` counts drops, so a streaming message dropped in one chunk and stored in a later one counts once for the drop. No migration: `events.counted`, `files.rereading` and `files.copies_dropped` of migration 800 are the owner flag and the reread state. The owner tests are seeded randomized property tests (no `hypothesis`: a dependency needs a justification and none was needed) |

The `pre-retro`, `post-retro` and `retro_failed` call sites are in `retrolaunch` (#26). |
| `cron` | managed block read, write, dry run |
| `usage` | query-time aggregation over counted events for `usage`, `show` and `export` |
| `plugin/` | `skills/audit/SKILL.md`, `skills/audit/references/marker.txt` and `profiles/audit-retro.yaml` (a claude-session profile that only adds denies) and `.claude-plugin/plugin.json` (names the plugin `session-audit`, so its name never depends on the installed directory name) |

## Data model

SQLite in WAL mode, additive migrations only. Tables:

- `files`: path (raw bytes), device, inode, size, offset, head length and hash, tail hash, rules version, skip-to-LF flag, parse-error and unknown-line counts, first and last timestamp seen, last usable timestamp, first working directory, first entrypoint, last version, last cost-state dollars, an invalid-cost flag, the count of copies not stored, a rereading flag, last read, status. Device and inode are stored as signed 64-bit integers via `signed_id`, and any comparison with a live or listed id must apply it. Per-file facts are replaced when the file is reread; session and agent values are derived from them and from counted events at query time.
- `sessions`: session id, project directory name, main file id, first and last ingest time. Identity only.
- `agents`: agent id, session id, parent tool-call id, agent type, file id. Identity only.
- `events`: one row per counted fact per file (a message's tokens, a tool call, a tool error, a denial, an interruption, a turn duration, a compaction): `key` (hash of the kind and the id, so kinds never collide), `ref` (hash of the paired tool call, on errors and denials), `file_id`, `file_path`, `line_offset`, `kind`, `ts`, `slot` (15-minute UTC), `session_id`, `agent_id`, `model`, `tool`, the four token counters with 5-minute and 1-hour cache writes, `seconds`, `native` (the line's `sessionId` is its file's session), `counted`. The owner of a key is the copy with the largest output tokens (messages only), then the earliest timestamp (null last), then the native copy, then the smaller file path, then the smaller offset; at most 8 copies of a key are stored (a worse copy is counted in its file's `copies_dropped`), and the owner is compared only with those, for every key a file read touches. Indexes: `events_key_file` (UNIQUE on `(key, file_id)`, which also serves lookups by `key`), `(file_id)` and `(session_id, counted)`. Pruned with the session.
- `pruned_sessions`: session id and prune time, so ingest does not resurrect a pruned session from an unchanged file.
- `harness_runs`: claude-session id, its `updated_at`, the Claude session ids it recorded (at most 64) and the snapshot (kind, labels as `key=value` strings, run, outcome, end reason, cost, turns, skill, repo, final); joined to sessions at query time.
- `retros`: id, key, state, reason, scope (descriptive) and resolved scope, skill, model, timestamps, csession id, session map, cost, turns, outcome, sandbox flag, again-of, lease fields, counts, dropped, redacted, warnings, `run_token`, `digest_sha256`. No collected ids or run files. Layout of the columns the Retro object needs (one choice of #23, written by `retroview.encode_*`, read by `retroview.load_retro`; a writer always writes every column, because the migration defaults `scope ''`, `resolved_scope '[]'` and `session_map '{}'` are not valid retros). Every capped column fits at the maxima (500 sessions, 64 labels of 400 characters, a 4096-character project):
  - `scope`: a short descriptive text (`name=value` words), at most 4096 characters cut at a character boundary, never read back as data.
  - `resolved_scope`: `{"flags": {labels, project, since, until, kind, outcome}, "sessions": [full ids], "since": ts|null, "until": ts|null}`, compact JSON with characters kept. The writer stores `labels` de-duplicated in typed order (`--label` may repeat; the reader and the schema require unique labels), and `scope` the same. Worst case: 500 ids 19,501 + 64 labels of at most 321 characters 20,737 + a 4096-character project of characters JSON escapes to six 24,578 + the other flags and keys under 600 = 65,185 of 65,536 in the test (a test builds and inserts it).
  - `session_map`: `{"sessions": [{ref, session_id, csession_id}]}`, about 47,500 characters at 500 sessions.
  - `retro_artifacts.artifact` (no column cap) is an envelope `{"artifact": <the checked artifact, intact>, "skipped": [...], "coverage": {...}, "metrics": {...}}`: the tool-written, unbounded parts (at most 1000 skipped rows, 1000 coverage rows, 6012 metrics) sit beside the artifact the model wrote. `load_retro` refuses an envelope over 8 MiB (`MAX_ARTIFACT_BYTES`) without parsing it; the maximum a writer can store is the 262,144-byte artifact plus about 0.4 MiB of the other parts (660 KB in all in the test) (a test computes it at the maxima).
  - Reuse window: `lookup_key` examines the newest 50 `done` rows of the key that pass the SQL pre-filters (`reason IS NULL`, id shape, a non-empty summary). A valid row behind 50 newer rows that pass the pre-filters but do not fit the layout is not reused; a re-run is the safe result. When nothing is reused, `unfit_retros` counts every `done` row of the key (at most 1000), not only the rows examined.
- `retro_artifacts`: retro id, artifact JSON (validated, redacted), summary. The only stored copy of the artifact.
- `retro_starts`: local day and retro id; the daily limit counts it together with live `digesting` rows; the only rows removed early are refunds of runs that never reached the model; `prune` removes rows older than two days.
- `retro_sessions`: csession id, retro id, csession directory, private directory, project directory name, cleanup state (`pending`, `done`, `incomplete`, `skipped`), forgotten time, creation time. It outlives the retro and drives self-exclusion and cleanup; removed only when cleanup is done, incomplete or skipped and no transcript root holds its project directory any more (or after 400 days); exclusion reads the table at every file open.
- `meta`: schema version, rules version, ingest lease, `last_ingest_at`, `last_complete_ingest_at`, `ingest_interval`, `fail_count`, `first_failed_at`, `last_failed_at`, `last_fired_at`.

Untrusted text lives only in `retro_artifacts` and the stored digest files.

Column bounds (migration 800; the documents above state only the 64 Claude session ids, the 500-session scope maximum and the retro and csession id shapes, so the rest are choices made here). Migrations are additive, so a bound cannot be loosened later and these are generous. Every TEXT column outside `retro_artifacts.artifact` and `.summary` has a `CHECK (length(...) <= N)`: ids, names, kinds, hashes and `status` at most 128 characters (`updated_at`, `status` and `meta.key` 64); `events.key` and `events.ref` 16 to 64 (a hash; the length is not fixed because the hash function is an ingest detail); paths and project directory names (`files.first_cwd`, `sessions.project_dir`, `harness_runs.repo`, `retros.scope`, `retro_sessions.csession_dir`, `private_dir` and `project_dir`) at most 4096; JSON columns also require `json_valid` and are bounded at 16,384 (`labels`) or 65,536 (`harness_runs.claude_session_ids`, `retros.counts`, `dropped`, `warnings`, `resolved_scope` and `session_map`; the design caps none of these but the last two, which are sized for 500 sessions, so they are generous); `meta.value` is at most 4,096 characters when it is text. `retros.id` (11), `key` and `digest_sha256` (64) and `retro_starts.day` (10) have the exact lengths of their documented shapes. `tests/test_store_schema.py` offers every bounded column an oversize value.

## Store

`store.py` opens the state directory and `state.db`; `log.py` writes `log.jsonl`; `migrations/` holds the schema. Opening is lazy (`Context.store()`), so `--version`, usage errors and `validate` never depend on the store; a command that never opens the store (a usage error, `--version`, `validate`) does not exit 20 `store_newer` for a newer store, and every command that does open it does.

- **Safety on open.** Missing directories are created 0700 and `state.db` 0600 (an explicit mode, with `fchmod`, so the umask never matters; the process umask is also 077 while files are created). An existing state directory, `state.db`, `-wal` or `-shm` that is a symlink, not a regular file, foreign-owned, group or other accessible, or hard-linked is refused with exit 12 `store_unwritable` and left as it is: the tool never repairs, moves or deletes what it did not create. The same code covers a corrupt or foreign SQLite file, a lock held past the 30 s busy budget (`retryable: true`; the budget covers the whole open, each retry gets only what is left, so the wait never exceeds 30 s), a full disk and a read-only file system. A `state.db` that is not exactly 0600 is refused on both the read-write and the read-only (`validate`) path. `state.db` is checked through the descriptor that is opened; SQLite then opens the same path, which only the user can change because the directory is 0700 and owned by the user.
- **Concurrency and secure delete.** Every connection waits up to 30 s for a lock; `PRAGMA journal_mode=WAL` fails at once instead of waiting while another process holds the file, so the whole open (switch, ledger read, migrations) is repeated inside the same 30 s budget, and a first open by several processes at once succeeds. `secure_delete` is a per-connection setting, so every connection that writes must set it: only `Store.conn` writes, and a second writer connection would have to set it too. `Store.checkpoint()` reads the `busy` flag of `wal_checkpoint(TRUNCATE)`: when a reader keeps the log from being reset, deleted bytes may still be on disk, so it raises a retryable `store_unwritable` instead of returning. A SQLite error maps to `store_unwritable` only when its result code is a storage failure (busy, locked, read-only, I/O, corrupt, full, cannot open, not a database); a bad statement (no such table or column, a syntax error, a constraint) is a bug in the caller and propagates unchanged. A `state.db` that cannot be opened for writing gives the hint "state.db is not writable"; `validate` opens it read-only.
- **Gateway.** `sqlite3` is a standard-library module the boundary test allows, so `state.db` is opened by `store.py`. Everything else the store needs from the file system goes through four gateway methods: `umask`, `mkdir`, `open_private` (never follows a symlink, never blocks on a FIFO, exact creation mode) and `lock_exclusive` (a polled `flock` with a deadline). The boundary test is unchanged.
- **Migrations.** Forward-only and additive (`migrations/base.py` refuses anything but CREATE TABLE, CREATE INDEX, ALTER TABLE ADD COLUMN and a `meta` seed). Each runs in one `BEGIN IMMEDIATE` transaction together with its row in the `schema_migrations` ledger and `meta.schema_version`, so a crash, a full disk or a concurrent opener leaves nothing half-applied and applies each exactly once. The store is "newer" when the ledger holds a number the code does not know; it is then refused (`store_newer`, exit 20) before anything is written, and never downgraded. `validate` uses `inspect_store`: a read-only connection (also `immutable` when no `-wal` file exists, so SQLite creates no `-wal` or `-shm` file beside a cleanly closed store), nothing created or applied (if the open without a `-wal` file fails because a writer created one meanwhile, it looks again and retries once with a plain read-only open), state `missing`, `ok`, `pending` or `newer`. A registry whose numbers repeat or are not ascending is a programming error (`ValueError`) raised by both `open_store` and `inspect_store` before anything is touched. An existing `state.db`, `-wal`, `-shm` or `-journal` must have mode exactly 0600 and the directory exactly 0700, so a setuid, setgid or sticky bit is refused too.
- **Numbering convention for later issues.** A migration's number is the owning issue's number times 100, plus 0 to 99 for further migrations of that issue (#9 owns 900 to 999, #13 owns 1300 to 1399). Migrations are applied by the ledger, in number order, whatever was applied before, so branches may land in any order; a migration may therefore use only objects created by itself or by a lower number. An issue adds one module `migrations/m<number>_<slug>.py` exporting `MIGRATION`, one import and one entry in `migrations/__init__.py` (a slot per known issue is reserved there, separated by blank lines so edits do not conflict), and extends the column pin in `tests/test_store_schema.py`.
- **Schema choices.** Timestamps are integer epoch milliseconds (`slot` is the epoch second divided by 900); hashes are lowercase hex text; transcript paths are BLOBs of raw bytes; `retros` carries the lease columns the data model lists (`lease_pid`, `lease_start`, `lease_expires_at`), and the lease logic that uses them belongs to the leases issue. Name-like columns carry length CHECKs and `events.kind`, `retros.state` and `retro_sessions.cleanup_state` are enums, so a column built for a name cannot take a message. `tests/test_store_schema.py` pins every column and refuses a column named for text outside `retro_artifacts`.
- **Log.** `LogWriter` validates each entry against pydantic models that mirror `schemas/log.json` (the writer accepts a strict subset of the schema: it refuses everything the schema refuses, and also what the schema allows but the writer never produces, such as a count of `1.0`; a test pins both directions), adds `ts` from the gateway clock, and appends one whole line with a single write to a file opened for append, under `log.lock` (an exclusive `flock`, 5 s). A torn last line is ended with a newline first.

## Concurrency

One `ingest` at a time: a lease on `meta`; retro leases follow the same single liveness rule (the holder runs with its recorded start time and the lease has not expired; a lease that is not live is taken over by compare-and-set, and every later state write of a holder is a compare-and-set that stops the holder when it lost the lease), see [Retro lifecycle](interface.md#retro-lifecycle) and [`ingest`](interface.md#ingest). Recovery takes a retro's lease first, so two processes never recover the same retro. A file is parsed with no transaction open and written in short chunks (events, offset, owners and per-file facts together), so a crash leaves the state of the last committed chunk and the counts never depend on read order; every connection sets `busy_timeout` 30 s; lease renewals use their own short transaction and are a compare-and-set on the holder's pid and start time (a recovery renews its claim the same way); every write transaction touches a bounded number of rows (at most 2,000 events or rows, each compared with at most 8 copies), so none is held near the 120 s expiry; housekeeping stops starting new items after 120 s. The live check and the row insert of `retro run` share one `BEGIN IMMEDIATE` transaction, which also reserves the daily-limit place. A holder of a place that is stalled in its `pre-retro` hook for over 120 s without renewing its lease stops counting in `reserved(day)`; its step-15 insert has no second check, so a day can reach limit + 1 starts in that case (accepted). `ingest --session` writes its harness snapshot itself without the ingest lease. A SQLite write lock is never held across a call to claude-session or a hook. `prune` takes the ingest lease for session retention and prunes a session in transactions of at most 2,000 rows; `retro delete` uses one transaction.

- **Lease API (`lease.py`).** A lease is `(pid, start token, expires_ms)`; `is_live` is the single rule (the PID runs with that start token, from `Gateway.process_start`, and `now < expires_at`; a zombie is not running, a field missing is free). A retro lease lives in the `lease_*` columns of its row (`RetroTarget`); the ingest lease is one `meta` row `ingest_lease` holding `''` or `<pid>|<start>|<expires_ms>` (`IngestTarget`), so one `UPDATE` compares and swaps all three fields and no migration is needed (the row is created on first take; a garbled value counts as free and is taken over by its exact text). `acquire` observes and takes in one `BEGIN IMMEDIATE`; `take_over(observed)` is the compare-and-set on the three observed fields for recovery, which observes first (rowcount 0 means skip). Every later write of the holder is a compare-and-set on its pid and start token: `Lease.guarded_update` for a retro row, `check_still_holder(conn)` inside the transaction of any other write (a state write elsewhere, an ingest chunk); `renew` and `release` compare the same way, so a stale holder extends and clears nothing of a new holder's. A lost lease is `CliError internal` (exit 1). `with lease:` runs one renewal thread (own connection from `Store.reopen()`, own short transaction every 30 s, expiry 120 s after it, retried at the next interval when the store is busy, ended by `close()`; it sleeps in 0.25 s ticks through the gateway so a stop is prompt); no write lock is held between renewals, so none spans a claude-session call or a hook. Signals are `interrupt.Signals`' and `retrolaunch`'s (#28, the Signals paragraph below), which call `close()` and `release()` on every exit path. Lease changes write no log line (the log's actions are `ingest`, `retro_state`, `retro_delete` and `prune`; a takeover is visible through the retro's own state change).

- **Signals (#28).** A retro run defers the first SIGHUP, SIGINT or SIGTERM from step 13 on (`interrupt.Signals.defer`): the handler records it and returns, and the Launcher polls it at its safe points, so no signal lands inside a transaction, a compare-and-set or a `finally` block and the handler never touches the database or starts a process. Before step 13 (flags, config, preflights, housekeeping, the plan check) the first signal raises `Interrupted` at once: everything unwinds through its own `finally` (the plan check removes its placeholder directory, a recovery gives its lease back), nothing of the run is stored, and `main` returns 128 plus the signal. What happens from step 13 on:

| Phase | First signal | Final state | Exit | What recovery finishes |
|---|---|---|---|---|
| step 13 (row insert) | the insert completes (or refuses); the run is then canceled at once, no hook runs | `canceled/interrupted` | 128 + n | nothing |
| `pre-retro` hook | the hook's process group is ended (SIGTERM, 5 s, SIGKILL); local files and digest removed | `canceled/interrupted` | 128 + n | nothing |
| step 15 (starts row, files) | the write completes; canceled; the start is refunded; files removed | `canceled/interrupted` | 128 + n | nothing |
| `start` | the call finishes (its 120 s timeout bounds it); a recorded session is stopped by its id (`stop --grace 5s`); refunded; cleanup | `canceled/interrupted` | 128 + n | a cut cleanup (`pending`) |
| adopting `exec` | the same signal is forwarded once to the exact child (`ProcessHandle.signal`); 30 s later, if it still runs, `stop` by the recorded id; 15 s later its group is ended; collect; cleanup; not refunded unless the outcome says the launch phase ended it | `canceled/interrupted` | 128 + n | a cut cleanup |
| collect | the call finishes; canceled | `canceled/interrupted` | 128 + n | a cut cleanup |
| before the artifact check (including the `validating` write) | no check is started; collect and the earlier rows above apply | `canceled/interrupted` | 128 + n | a cut cleanup |
| artifact check (#29) | it finishes (local, bounded); its verdict stands | `done` or `failed` | 128 + n, no envelope | a cut cleanup |
| final write, cleanup, post hooks | cleanup continues for at most 30 s from the signal or from the start of the cleanup, whichever is later (a call in flight past that is ended); post hooks are ended (SIGTERM, 5 s, SIGKILL) | unchanged | 128 + n | the `pending` cleanup row |
| a second signal at any of them | `Interrupted` at once, code of the first; the lease is released by compare-and-set; a running `start` call or hook group is ended; the exec child is abandoned to its own timeout | the last write (`digesting`, `running`, `validating` or the mapped final state) | 128 + first | recovery by the recorded id: `failed/runner_lost` for a non-final retro (the exec child is stopped by its id), the cleanup retry for a final one; no `post-retro` (no outbox) |

A signal inside the artifact check keeps its verdict (the check is local and bounded and writes nothing: the verdict and the stored artifact reach the store in the one transaction of the final write). `stdout` carries nothing for these exits (`--json` included); progress notes on a closed stderr are swallowed (`stderr_line`), and a failed stdout write is exit 1 as everywhere. SIGPIPE stays ignored.

## Error handling

A bad line, an unsafe file or an unknown shape is counted and skipped, never fatal; every line is parsed inside one guard. A source that cannot be read at all (an unusable root, an unwritable store) is exit 12 with a reason. A retro failure keeps its state and reason in the store and is reported by exit code. Every `claude-session` call is checked against its exit code and JSON envelope; any result outside the outcome mapping table is `claude_session_error` (exit 12), and a skill, claude-session version or launch-settings problem (including an unsafe plugin directory, an over-long or non-ASCII project directory name) is found by the preflight or the plan check and refused before a row exists; a `start` that fails after allocating records any id it printed after validating it, and forgets the session like any other. A failed `start` leaves a session the tool records in `retro_sessions` and forgets like any other. Every claude-session call has a timeout and its own process group, and a run has an overall deadline. A recovery or cleanup that cannot finish leaves the cleanup state pending or incomplete and `validate` warns; cleanup is one idempotent step list repeated by housekeeping, so a repeat `forget` that reports not found cannot turn an unfinished purge into done, and recovery defers (warning) when claude-session cannot answer. A `retro_state` log entry is appended after the transaction it describes commits; a crash between the two loses that log entry (the row is authoritative).

## Test strategy

- All process, file-outside-store, clock and crontab access go through `gateway.py`; tests substitute fakes (`tests/fakebin/` holds a fake `claude-session`).
- Test layout. `tests/conftest.py` gives every test a private home, XDG and state directory and a `PATH` that starts with tripwire programs, and guards `subprocess.Popen` so only fakes can start `crontab`, `claude` or `claude-session` (by any argv element or `sh -c` word; a shell, `env` or interpreter must keep the tripwire directory first on `PATH`). `tests/fake_gateway.py` is the scriptable gateway for modules above it, `tests/fake_claude_session.py` scripts the fake program `tests/fakebin/claude-session` and validates every scripted document and exit against the pinned schemas, `tests/schemas.py` validates documents against this tool's `schemas/` and the pinned claude-session schemas, `tests/golden.py` compares `--json` output with golden files, and `tests/procs.py` checks that a test's processes are gone. `tests/schemas/claude-session/` holds claude-session's published `cli/*.json` schemas copied by hand (never imported) and pinned to one release; its `PINNED` file names the release and commit. To re-pin: copy `schemas/cli/*.json` from the newer claude-session tag into `tests/schemas/claude-session/cli/`, update `PINNED` and `PINNED_VERSION` in `tests/schemas.py`, and run the tests. `tests/schemas/` never gets an `__init__.py` (it would clash with `tests/schemas.py`).
- A synthetic transcript corpus with duplicate-block lines, corrupt, unterminated and NUL lines, backwards timestamps, subagents, compaction, resume, a fork with copied history, unknown line types and a symlink, FIFO and hard-linked file. Golden `--json` files for every command; every real output validated against `schemas/`.
- Counting, cost basis and slot bucketing property tests, including the owner rule: any ingest order, a rewritten owner file, a partial copy of a streaming message and a rebuild give the same counted events for keys with at most 8 copies (for more, see the interface.md residual risk); a failed Bash call yields one counted `tool_call` and one counted `tool_error`; a user line with both a denial and an interruption yields two events; session values equal a recount from events and per-file facts.
- Redaction and sanitizer tests with a fuzz corpus (including forged closing fence tags, adversarial inputs for linear time at 64 KiB and the invisible and bidi code points the allowlist replaces).
- Retro lifecycle tests against the fake `claude-session`: the order of checks, skill and version preflight, the plan check, every row of the outcome mapping table, every artifact check, signals, and the launch plan check (every safety setting, the project directory name length), a failed `start`, the deadline, lease takeover, cleanup retries by recorded id and recovery that defers without claude-session.
- Reader and counting tests for the hardening rules: `totalCostUSD` of `1e999`, `NaN`, `-1`, `true`, `"5"` and `2e6` ignores the line and sets `cost_invalid`, and every numeric field of an event is validated before storage (`--json` stays valid); the owner rule with 9 and 300 copies of one key keeps 8, counts `copies_dropped` and stays linear, a rebuild of a file with millions of events commits in bounded batches and never holds a transaction near the lease expiry, and a crash between batches resumes with `rereading` set.
- Retention and exclusion tests: a `retro_sessions` row survives while its project directory exists (also with `remove_run_transcripts: false`) and is removed once the directory is gone or after 400 days, and a retro directory created during a long ingest is excluded because the table is read at every file open.
- Retro launch hardening tests: the bundled plugin of a wheel installed with umask 002 passes the preflight while a configured directory with one group-writable file or directory is refused (`unsafe_plugin_dir`, exit 12), skill names with `/`, `..`, uppercase or over 64 characters exit 2, a `start --dry-run` plan with an unknown extra `origins` key set by config fails closed, a non-ASCII session directory path is refused, `start` output with a malformed id or directory is refused without calling `forget` or `stop`, a `start` that times out after printing an id is recorded and forgotten, housekeeping stops after 120 s with `recovery_deferred`, and a stale holder's renewal does not extend a new holder's lease.
- Text tests: model text of 1,500 U+0344 characters or a short secret expanded by `[REDACTED:<kind>]` is stored within its schema cap, and an error message or hint carrying escape sequences is sanitized on stderr.
- Packaging test: the built wheel contains `session_audit/plugin/.claude-plugin/plugin.json` (a hidden directory) and the installed plugin's name is `session-audit`.
- `live` tests (never in CI): the real reader on a real directory, and one real retro round trip. Each fact in Live verification is a named test.
- `make verify` (ruff, pyright, pytest without `live`, markdown lint) must pass before every commit.

## Redaction patterns

The set lives in `src/session_audit/redact_patterns.toml` (package data, read with `importlib.resources`; hatch's wheel target takes every file under the package). The file holds 47 patterns (the private-key block is code, not a pattern). One entry per pattern: `name`, `kind`, `regex`, optional `group` (the part that becomes the marker, so header, flag and key names stay readable) and optional `extend` (how a value that reached the 16,384 character bound is continued in code). Kinds and entries:

- `token`: AWS access key ids, GitHub (classic and fine-grained), GitLab, Slack (bot, app, webhook path), Telegram bot, Anthropic, OpenAI, Google (API key, OAuth), Stripe (secret, restricted, webhook), npm, PyPI, Hugging Face, SendGrid. A literal prefix of 4 or more characters (`ghp_`, `github_pat_`, `glpat-`, `xox?-`, `xapp-`, `sk-ant-`, `AKIA` and the other AWS prefixes, `ya29.`, `sk_live_`, `whsec_`, `npm_`, `pypi-`) has no word boundary before it, so `xxghp_...` and `kAKIA...` are redacted; the short or ambiguous prefixes (`sk-`, `AIza`, `hf_`, `SG.`, the Telegram digits) keep their lookbehind because dropping it would redact ordinary words such as `task-...`.
- `jwt`: `eyJ` plus two more base64url parts (the third may be empty), or the two-part form `eyJ...<.>eyJ...` of an unsigned (`alg: none`) token.
- `private_key`: not a regex. `str.find("-----BEGIN ")`, the header regex of the interface, then `str.find` of the same label's END line; none means the end of the part.
- `url_userinfo`: `user:secret` between `://` and the last `@` before `/`, `?`, `#` or white space (a password may hold `@`); a password over 16,384 characters is redacted to its end (up to the last `@` of the run); a userinfo without a colon, such as `ssh://git@host`, stays.
- `cookie`, `auth_header`: `Cookie`/`Set-Cookie` values to the end of the line or a quote; `Authorization`, `Proxy-Authorization` and the common API-key headers (`:` or `=`, the value possibly on the next, indented line); a bare `Bearer <16+ characters with a digit>`. A shorter or digit-free bearer value is kept on purpose (prose such as "bearer authentication-mechanism" must stay; a real bearer token is long and has digits). `curl -b`/`--cookie name=value` is `cookie` too.
- `cli_secret`: `--<...>password|passwd|passphrase|token|secret|api-key|access-key|private-key|credential(s)` followed by `=` or a space and a value (a single leading `-` is part of the value, a leading `--` is the next flag); `-u|--user|--proxy-user user:pass` (also attached, `-uuser:pass`; numeric uid:gid stays); `-u user -p pass` and `-p=pass`; `sshpass -p pass`; `openssl -pass|-passin|-passout pass:VALUE` (`env:`, `file:` and `fd:` name a source and stay). A bare `-p X` and `mysql -pVALUE` are NOT redacted: `-p` is a port or a prefix in most tools (`ssh -p 22`, `ls -p`) and `find -print0` shows the cost of guessing; only the forms above that name a login command, `sshpass` or the equals sign are safe.
- `json_secret`: JSON (plain and escaped inside another string), Python-dict, YAML and XML keys that END in a secret word (`password`, `secret`, `token`, `api_key`, `authorization`, `cookie`..., and `pass`/`pwd` when no letter precedes them, so `bypass` stays), so `max_tokens`, `token_type` and `tokenizer` stay; dashes and dots may be part of the key (`my-api-key`, `spring.datasource.password`). Quoted values of any length (a number such as `"password": 12345678` too), bare YAML values of 6 or more characters: at the start of a line they run to the end of the line (a type annotation such as `token: str = None` stays), in flow context (`db: {password: x}`, after `{` or `,`) they stop at white space, a comma or a bracket (so `def f(a: int, token: str = None, n: int = 3)` and `{ token: string; user: User }` keep their other parts), with or without a space after the colon and with a quoted key (`'password': x`). XML: `<password>x</password>` and `<add key="password" value="x"/>`. A bare `key` or `tokens` array is not a secret word.
- `assignment`: names that CONTAIN TOKEN, SECRET, PASSWORD, PASSWD, PASSPHRASE, KEY, CREDENTIAL or AUTH (the interface says "containing", so `MONKEYS=bananas1` is redacted on purpose); names may hold `-` and `.` and be up to 128 characters on each side of the word. `NAME=value` takes a quoted value or a bare one of 6 or more characters up to white space or a quote (a `,` `;` `&` or `)` inside it leaks no tail) that does not start with `$`, a backtick, a bracket, `(`, `<` or a marker; `NAME = "value"`, `NAME := "value"` and `const name: string = 'value'` take a quoted value; a line that starts with `NAME = value` takes a bare value of 6 or more characters unless the value is a call (`token = get_token()` stays). Also: SQL `IDENTIFIED BY '...'` and `PASSWORD '...'`, netrc `login X password Y` and a `password Y` line whose value has a non-letter, and connection strings `;Pwd=...;`/`;Password=...;`.
- `env_value`, `prefix`, `encoded`: see below.

Choices, with the reason:

- Linear time. Every repetition is bounded (16,384 at most) and none nests; a branch inside a repetition has alternatives that cannot start with the same character; two adjacent repetitions never share a starting character (a test walks each compiled pattern with `re._parser`, descends into every construct it knows, and fails loudly with "update the walker for this Python" on an opcode it does not know or when `re._parser` is unavailable; the check is conservative and lives in the tests only). A pattern that scans a run starts only at the run's start (a lookbehind on the same class) or at an anchored literal, so overlapping attempts cannot multiply. Timing tests compare 16 KiB with 64 KiB (4x linear, 16x quadratic) over 71 adversarial families (runs of alphanumerics, `-`, `.`, `=`, spaces and newlines, repeated partial prefixes, names and flags) and give every pattern alone an absolute ceiling of 2 s per family at 64 KiB. The `jwt` run bound (16,384) is large on purpose: a bound that stops short would leave the tail. The same holds for values: a value that reaches 16,384 characters is continued in code over the rest of the same character run (the `extend` key), so a 20,000 character password leaves no tail.
- Spans, then one pass. Every detector yields spans on the NFC text; overlapping or touching spans merge into one marker (the kind of the leftmost, longest). Redaction is idempotent: a span that is already a marker is left. Patterns and prefixes read a folded copy of the text (each character whose decomposition starts with an ASCII letter or digit is replaced by that base, same length, so offsets carry over) and a token, JWT, mask or prefix span also takes the combining marks after it: a mark after the last character of a token composes with it under NFC and would otherwise defeat the match. The fold only ever matches more. Redaction is applied to NFC text; confusable characters (zero-width characters, fullwidth forms, homoglyphs inside a token) are not folded: a contrived residual limit.
- Literal masks. `str.find` loops, longest first, values of at least 8 characters after surrogate fixing and NFC, at most 128 source values (`MAX_MASKS`), none over 65,536 characters (it cannot occur in a part). Each value also adds its JSON string-escaped form (`json.dumps(value)` without its quotes, ASCII-escaped and not), when it differs, because tool output is often JSON; these are at most two more per value and are not counted against the 128. A multi-line value also adds its lines and its stripped form; when more than 128 masks are found, the whole values win, then the stripped forms, then the per-line forms (at most 4 per value, the longest lines), and the warning counts what was dropped. `find_encoded` and `redact_encoded` use the same normalization, length filter, size cap and count cap. Case-sensitive and exact. The names are the `mask_env` entries plus every variable whose name contains one of the secret words in any case (so `SSH_AUTH_SOCK` is masked). A warning names a `mask_env` variable only when it is set and short; secret-named variables are counted, never named; no warning holds a value.
- Prefixes. `str.find` per prefix, then the whole run of `[A-Za-z0-9_-]` after it (8 or more), consumed so the scan stays linear. No word boundary: the interface says "starting with a prefix".
- Encoded forms (for artifact validation, #29). base64 at the three alignments (leading characters that depend on the preceding bytes and the last, partial character are left out; standard and url-safe alphabets; padding optional), hex in any case and percent-encoding (`quote`, `quote_plus` and all-bytes, hex digits in any case), matched with `str.find` on the text (ASCII-lowercased, same length, for hex and percent). The base64 search ignores spaces, tabs and line breaks inside the text (MIME wrapping at 64 or 76 columns), with the hit mapped back to the original offsets. A value over 1 KiB is checked by its first and last 512 bytes on purpose: the middle of such a value is not searched, and a part that holds only the middle is not a leak of the head or the tail (verified by a test). A base64 hit also takes the one character and the padding the needle left out.
- Never a value in any output. `Redactor` has `__slots__`, a `repr` of counts, and refuses pickling and copying; errors name no value; the tests use a sentinel and scan stdout, stderr and the log capture.
- The work bound. The first 65,536 code points of a part are kept, but redaction reads a window of twice that, so a secret or mask that starts inside the bound and ends after it is redacted whole and no head fragment survives; the output then ends at the bound, or after the marker of a match that starts inside it (the work is at most twice the bound). A match that starts at or after the bound is not kept.
- A private key whose BEGIN line was lost (a tail-truncated output): an `-----END ... PRIVATE KEY-----` line outside any block redacts the key body before it, back to the previous blank line or at most 4,096 characters. Labels are upper case, as for BEGIN.
- Limits, stated. Redaction is best effort. Secrets held in a process's locals appear in no traceback, repr, pickle, copy or warning of this module (the values live in the process environment only; no exception path carries them), so a crash report holds no mask value. A bare `Bearer` value that is short or has no digit, a bare `-p X`, and confusable characters inside a token are known misses.
- The cut moves BACK to a marker's start, never forward: the result never exceeds the cap (it can be shorter by up to a marker). NFC runs before it, so 1,500 U+0344 count as 3,000 code points and are cut to 1,500.
- Unicode drift. `textsafe.sanitize` uses the interpreter's Unicode database (U+2FFC: a marker on 3.12, kept on 3.13), so `section_sha256` and therefore the retro key can differ between Python versions for text holding newly assigned code points. `redact.UNICODE_VERSION` exposes the database in use. It is deliberately not in the key (the interface defines the key); the effect of a Python upgrade is a re-run instead of a stored-retro hit for such text. `redact.DIGEST_FORMAT` (2 since #22, which neutralizes an opening `<untrusted` tag in text as well) is the format number of the interface; `fencing.FencedDigest.unicode_version` carries it for the caller (the manifest schema is closed and does not).
