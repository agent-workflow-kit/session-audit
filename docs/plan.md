# session-audit: implementation plan

Status: planned against architecture v1.33 and design guide v1.17. This plan implements [`interface.md`](interface.md) and [`design.md`](design.md). Each stage is split into issues; an issue is expanded into bite-sized test-first steps when it is picked up. This file holds no full-code steps.

## Conventions for every stage

- **Interface first, test first.** A behavior is written as a failing test, then the code. `interface.md` is the single normative source: when code and interface disagree, the interface is fixed in the same PR and `awkit-docs/interface-registry.md` is updated.
- **Gateway boundary.** Every subprocess, every file access outside the store, the clock and the crontab go through `src/session_audit/gateway.py`, so tests substitute fakes. No module imports `subprocess` or opens a transcript directly.
- **Fakes and pinned sibling schemas.** `tests/fakebin/claude-session` is a fake that prints outputs validated against claude-session's published schemas, copied into `tests/` pinned to a version (copy, never import). It can be scripted per test for every row of the outcome mapping, a failed `start`, a dry run with a changed setting, a forgotten session and a hung call.
- **Process and live split.** Process tests use the fakes and a synthetic transcript corpus. Anything that needs the real Claude Code or the real claude-session is marked `live`, deselected by default and never run in CI. Each fact in the design's Live verification table has a named test.
- **Golden files.** Every `--json` output has a golden file and is validated against `schemas/`. Schemas are generated by the private generator during design; from implementation on, they are edited by hand with the interface and checked by `check-jsonschema --check-metaschema` exactly as CI runs it, and `config.example.yaml` is validated against `schemas/config.json`.
- **Spike regressions.** The facts from the design spikes are regression tests: message-id dedupe, backwards timestamps, corrupt and unterminated lines, the 15-minute slot rule, a launch from the default state directory, and the retro round trip.
- **`make verify`** (ruff, pyright, pytest without `live`, markdown lint) passes before every commit. Markdown rule: one line per paragraph and per list item.
- **No private content** in any repo file, test fixture or example. Test corpora are synthetic.
- **Dependencies:** `pyyaml` and `pydantic` only; a new dependency needs a justification in `design.md`.

## Stage 0: Skeleton, config, store and gateway

**Goal**: A runnable CLI shell with the safety foundations every later stage uses.
**Success Criteria**: `session-audit --version` prints the package version; `validate` runs offline and prints the documented document; config loads with drop-ins and refuses an unsafe config; the store opens, migrates and refuses a newer version; every command exists and exits with the documented usage errors; all outputs validate against the schemas.
**Tests**: config precedence and drop-in merge; ownership, symlink and mode refusal; durations and time-argument grammars with limits; `config.example.yaml` against `schemas/config.json`; store migration, `store_newer`, file modes `0600` and `0700`, `secure_delete`; lease acquire, renew and compare-and-set takeover with a dead holder; error envelope and exit-code table; gateway fakes; golden `validate` output; error messages, hints and warnings carrying escape sequences are sanitized on stderr.
**Status**: Not Started

## Stage 1: Reader and parser

**Goal**: Read Claude Code transcripts safely and incrementally and turn lines into events.
**Success Criteria**: Every file under the roots is discovered or skipped with a counted reason; unsafe files never open; a partial last line waits for the next run; a rewritten, truncated or replaced file is detected and reread; each row of the transcript field map yields the specified event.
**Tests**: synthetic corpus with symlinks, FIFOs, hard links, wrong owner, 8 MiB+ records, NUL bytes, lone surrogates, deep nesting, huge integers, unterminated and corrupt lines, backwards timestamps, unknown line types, subagent files before parents; head and tail hash change detection; budgets and resume; one fixture per field-map row; property test that line-by-line and chunked reads give the same events; `totalCostUSD` of `1e999`, `NaN`, `-1`, `true`, `"5"` and `2e6` ignores the line and sets `cost_invalid`; every numeric field of an event is finite, non-negative and capped before storage and `--json` stays valid.
**Status**: Not Started

## Stage 2: Counting, store queries and the deterministic commands

**Goal**: `ingest`, `sessions`, `usage`, `show`, `export`, `prune` and retention over the events table.
**Success Criteria**: counted events are independent of ingest order, rewrites and rebuilds; every counter, `--by` dimension, `--tz`, totals, ordering, limits and `truncated` behave as documented; cost carries its basis; `prune` applies every retention key in the documented transactions; `ingest` is safe under overlap and reports `already_running` once.
**Tests**: owner-rule property tests (any order, rewritten owner file, fork copies, partial copy of a streaming message, rebuild); tool call and error as two events; denial plus interruption as two events; error model and tool by the paired call; cost mismatch flag and the all-or-null reported cost under `--since`; price table prefix matching; each retention key; concurrent `ingest` processes; 9 and 300 copies of one key keep 8 and count `copies_dropped` in linear time; a reread of a file with millions of events deletes in bounded batches, resumes after a crash with `rereading` set and never holds a transaction near the lease expiry; a `retro_sessions` row survives while its project directory exists and goes once it is gone or after 400 days, and exclusion is read at every file open; golden outputs; the store-size measurement on a large synthetic corpus with a recorded budget.
**Status**: Not Started

## Stage 3: Harness enrichment

**Goal**: Optional claude-session snapshots joined to sessions at query time.
**Success Criteria**: `ingest` captures facts only for runs that are final, keyed by claude-session id over the documented window; the join uses only recorded Claude Code session ids; a missing or old claude-session is a reported state, never an error for the deterministic commands; `ingest --session` captures one session without the ingest lease.
**Tests**: fake claude-session with forgotten sessions, label grammar, a huge list, `status` failures and a hostile document; join tests including a transcript with no match; no-guess test (directory names never match); snapshot refresh on `updated_at`; minimum-version check.
**Status**: Not Started

## Stage 4: Digest

**Goal**: Build the bounded, redacted, sanitized, fenced digest and manifest, and `retro run --dry-run`.
**Success Criteria**: the digest follows the layout, numbering, budget priority and coverage statement; redaction, sanitizing and fencing run in the documented order with linear-time guards; `digest_sha256` and the content key are stable for unchanged input; the plan prints without storing or calling any model.
**Tests**: priority-drop tests; size caps; redaction corpus (token shapes, key blocks, headers, secret-named assignments, masked environment values, encodings, key tails over 8 KiB); sanitizer corpus (bidi, invisible, tag characters, escapes, lone surrogates); forged closing fences; linear-time tests at 64 KiB; NFC and redaction run before the length cut (1,500 U+0344 characters stay within the cap); key stability and sensitivity tests; golden digest and manifest files.
**Status**: Not Started

## Stage 5: Retro launch and lifecycle

**Goal**: `retro run` end to end against claude-session: checks, launch, outcome mapping, collection, cleanup, recovery and hooks.
**Success Criteria**: the order of checks is exactly the documented one; the plan check and preflight cost nothing when they refuse; `start` then the adopting `exec` run in the session directory; every outcome maps to the documented state, reason and exit code; cleanup is one idempotent step list; recovery by recorded id works at `retro run` start and in `prune`; the daily limit reserves and refunds as specified; signals stop the exact session; `pre-retro`, `post-retro` and `post-attention` behave as documented.
**Tests**: fake-claude-session scripts for every row of the outcome mapping, a failed `start` (the leaked session is forgotten), a dry run with each safety setting changed, a lease takeover race between two `retro run` processes with the same key, a crash at every step of the order followed by recovery, `forget --purge` repeats and `purged: false`, SIGINT and SIGTERM at each step, hook veto, escalation, timeout and process-group kill, the daily limit under concurrency, recovery deferring without claude-session; the bundled plugin of a wheel installed with umask 002 passes the preflight while a configured directory with one group-writable entry is refused (`unsafe_plugin_dir`, exit 12); skill names with path characters exit 2; an unknown `origins` key set by config fails the plan check closed; a non-ASCII session directory path is refused; `start` output with a malformed id or directory is refused without `forget` or `stop`; a `start` that times out after printing an id is recorded and forgotten; housekeeping stops after 120 s; a stale holder's renewal does not extend a new holder's lease; the launch from the default state directory (a `live` test).
**Status**: Not Started

## Stage 6: Artifact, plugin and retro commands

**Goal**: The bundled skill, the profile, strict artifact validation and `retro list|show|delete`.
**Success Criteria**: an artifact is accepted only when every validation check holds; invalid evidence is dropped and counted; stored text is redacted and sanitized; the bundled plugin loads under the sandbox with a marker the skill echoes; `retro show --json` is the stable contract; the wheel contains the plugin and its manifest.
**Tests**: each validation check and each failure reason; depth, size, big-integer and surrogate guards; candidate risk written by the tool; secret scan of model text; model text expanded by NFC or a redaction marker is cut to its schema cap after normalization; terminal-escape sanitizing on every human output; plugin manifest and wheel-content test; `live`: the retro round trip, injection corpus, the placeholder-entry behavior, the report-command form, and the cleanup of the run's own transcript.
**Status**: Not Started

## Stage 7: Cron, validation, documentation and release readiness

**Goal**: Periodic operation and everything needed to call 0.x usable.
**Success Criteria**: `cron install|uninstall` write and remove only the managed block and report `--dry-run` outcomes; `validate --probe` checks claude-session and the sandbox; README and `config.example.yaml` match the interface; the live-verification checklist (reader on a real corpus, macOS paths, a real fork pair, the retro's transcript directory name, long directory names, ancestor `CLAUDE.md` loading) is executed and recorded; the first interface-registry update lands.
**Tests**: cron block golden files and malformed-block refusal; `ingest_stale` and `ingest_failing` behavior; the live checklist; a full-day soak of hourly `ingest` against a real directory.
**Status**: Not Started

## Version roadmap

- **0.x**: stages 0 to 7. Each stage merges as it completes; releases are automatic from PR titles.
- **1.0** qualifies when: the live-verification checklist has no open item, the retro round trip and the injection corpus pass on Linux and WSL, macOS is checked locally, the interface has had no breaking change for two minor releases, claude-session has pinned the fields session-audit relies on, and the events-table size target is met on a real corpus.
- **1.x** (additive): `--mode interactive` through agent-spawn; a `browse` TUI (usage drill-down, retro viewer); a `retro publish` action (a summary posted or a note written) with `--dry-run`, `--yes`, `--actor`, an audit record and a human confirmation; enrichment through agent-spawn and review-run records; retro resume; a rollup of old events into slot totals if the table is too large; a dollar view of review spend once review-run reports `cost_usd`; more digest item kinds.
- **2.0**: nothing planned.
